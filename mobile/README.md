# Mobile — White-Label Device Policy Controller (Kotlin)

Android app (Kotlin, Jetpack Compose) that runs as **Device Owner** on financed phones. It enrolls the
device with the platform, hydrates its UI from the tenant's dynamic branding, and enforces the
four-phase lock lifecycle (Active → Grace → Soft Lock → Hard Lock) with on-device anti-tamper and
offline safeguards.

📸 **Screenshots:** [`screenshots/`](screenshots/) — regenerated by CI on every push.

## What the app does

| Requirement | Implementation |
| --- | --- |
| Device Owner provisioning via 6-tap QR / Zero-Touch | `ProvisioningModeActivity`, `PolicyComplianceActivity`, `EnterpriseAdminReceiver` parse `EXTRA_PROVISIONING_ADMIN_EXTRAS_BUNDLE` (`tenant_id`, `provisioning_token`, `api_gateway_url`) |
| Enrollment telemetry (dual IMEI, serial, MAC, OS, patch level) | `DeviceRepository.enroll()` → `POST /api/v1/devices/enroll` |
| Dynamic branding | `GET /api/v1/tenants/{id}/config` → `TenantTheme` (colors, corner radius), Coil pre-caching (50 MB disk cache) |
| Encrypted storage | `SecureStore` — EncryptedSharedPreferences (AES256_SIV keys / AES256_GCM values) + device-protected lock flag for direct boot |
| 10 UserManager restrictions, EFRP, lock task, always-on VPN, passcode | `DeviceSecurityManager.applyFinancingSecurityPolicies()` |
| Soft lock | Suspends non-essential apps, blocks outgoing calls (emergency still allowed) |
| Hard lock | Lock Task Mode + persistent HOME activity + status bar disabled; full-screen takeover with payment QR, account ID, IMEI, support & emergency dial |
| Dual-channel commands (< 3 s) | FCM data messages (`PushService`) + retained MQTT topic (`EnforcementService`) + heartbeat polling, all ACKed |
| Offline heartbeat lockout | `SecureClock` (monotonic `elapsedRealtime` + trusted server-time offset, reboot detection) + `EnforcementEngine` |
| Offline unlock tokens | `OfflineUnlockCode` — same HMAC-SHA256 algorithm as the backend (shared test vector) |
| Integrity checks | `IntegrityChecker` — su binaries, root packages, test-keys, verified boot / bootloader state, ADB |
| Payment whitelisting in kiosk mode | `CheckoutWebView` validates every navigation against `repayment_settings.whitelisted_domains` |
| Loan payoff | `RELEASED` → all restrictions cleared and Device Owner relinquished |

## Build

Requirements: JDK 17+, Android SDK 35.

```bash
cd mobile
./gradlew assembleDebug                 # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest             # unit tests
./gradlew recordPaparazziDebug && ./scripts/collect-screenshots.sh   # regenerate screenshots
```

### White-label builds

Tenant branding is fetched at runtime, but the APK's launcher name/icon color, package id and API URL can be
compiled per tenant:

```bash
./gradlew assembleRelease \
  -PapplicationId=com.acme.dpc -PtenantName="Acme Credit" -PtenantPrimaryColor="#E4002B" \
  -PapiBaseUrl=https://api.acme-credit.com/ \
  -PfirebaseAppId=... -PfirebaseApiKey=... -PfirebaseProjectId=... -PfirebaseSenderId=...
```

Release signing uses `DPC_KEYSTORE_PATH`, `DPC_KEYSTORE_PASSWORD`, `DPC_KEY_ALIAS`, `DPC_KEY_PASSWORD`
(in CI: repository secrets `DPC_KEYSTORE_BASE64`, `DPC_KEYSTORE_PASSWORD`, `DPC_KEY_ALIAS`, `DPC_KEY_PASSWORD`).
Without them the release APK is built unsigned.

### Testing on a device / emulator

Device Owner can be set on a freshly wiped emulator without QR provisioning:

```bash
adb install app/build/outputs/apk/debug/app-debug.apk
adb shell dpm set-device-owner com.inditech.dpc/.admin.EnterpriseAdminReceiver
```

Then open the app and use **Enter enrollment code manually** with the values from the backend's
`POST /api/v1/admin/tenants/{id}/provisioning-tokens` response (use `http://10.0.2.2:8080` as the API URL
when the backend runs on the host machine).

For QR provisioning, encode the `qr_payload` JSON from the same endpoint into a QR code and tap the setup
wizard welcome screen six times.
